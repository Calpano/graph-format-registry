= JSON Graph Entry Format 8.0.0
:toc:

The JSON Graph Entry Format (GEF) is a lenient JSON graph format and a *superset* of
link:../connected-json/connected-json-8.0.0.adoc[Connected JSON] (CJ): every valid CJ file is also a valid GEF file,
but GEF additionally accepts relaxed, convenient dialects of CJ-like JSON. Where CJ is a *strict* graph **interchange**
format (one canonical way to express each construct), GEF is a forgiving **entry** format meant for hand-authoring and
for importing varied inputs.

Its defining trait is *graph-at-root*: a graph may be stated directly at the document root (`nodes`/`edges` with no
`graphs` wrapper), so the file itself *is* a single graph. GEF also relaxes parsing: numeric ids are coerced to strings
(`12` becomes `"12"`), any property not defined by the spec is read as `data`, `source`/`target` (and
`sources`/`targets`) are shortcuts for the canonical `endpoints` array, `graph` is an alias for `graphs`, and a bare
string label is shorthand for `{ "value": … }`. None of these are new graph-model features — they are syntactic
conveniences over the CJ model.

== Features

GEF inherits the full Connected JSON graph model (it is a superset), so its graph-model feature support mirrors
link:../connected-json/connected-json-8.0.0.adoc[CJ 8.0.0]. The GEF additions (graph-at-root, lenient ids, property
aliases, arbitrary-keys-as-data) are syntactic, not new features.

[source]
----
