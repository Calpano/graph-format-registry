= Format Catalog

Every format and model we currently know, with its identity fields as found in
the Connected JSON source (`cc-gio-ui/src/lib/data/format-*.json`). This is the
working sheet for **fixing and homogenizing ids**. Each entry lives at
`formats/<family>/<format-id>.adoc`.

Columns:

* *format-id* — the canonical slug; becomes the AsciiDoc filename (`<format-id>.adoc`). The ddot subject is the slug qualified into the `format:` namespace (e.g. `format:adjlist`); the filename stays the bare slug. Includes the version suffix where the format has one.
* *version* — spec version, when the format has one.
* *released* — release date of that version, ISO 8601 (partial like `2025-04` allowed); blank = unknown.
* *type* — `format` (a serialisation) or `model` (a conceptual model, not a serialisation).
* *cat* — category: `text` | `json` | `xml`.
* *label* — display label.
* *alt names* — alternative names.
* *source* — source JSON file.

== Reader-backed formats (GraphInOut)

Audit of the GraphInOut `reader-*` modules (`com.graphinout.reader.*`): every
format with a reader is now in this registry. Most were already present; these
11 were added from the reader audit (ported to `formats/<id>/<id>.adoc`):

[cols="2,1,2,2,1",options="header"]
|===
| format-id | cat | label | file extensions | wikidata

| d2              | text | D2 (Terrastruct)                  | .d2                          |
| ddot            | text | DDot.it Triple Text Format        | .ddot, .ddot.txt             |
| sparse6         | text | sparse6                           | .s6, .sparse6                |
| digraph6        | text | digraph6                          | .d6, .digraph6               |
| gtfs            | text | GTFS (General Transit Feed Spec)  | .gtfs.zip, .gtfs             | Q5532250
| mermaid         | text | Mermaid                           | .mmd, .mermaid               | Q110961986
| neo4j-json      | json | Neo4j APOC JSON Export Format     | .neo4j.json, .neo4j-export.json |
| pg-json         | json | PG-JSON (Property Graph Format)   | .pg.json, .pgjson            |
| tripletext      | text | TripleText Format                 | .tt.txt, .tt, .tripletext    |
| rdf-nquads      | text | N-Quads                           | .nq                          | Q31398150
| connected-json5 | json | Connected JSON5                   | .cj.json5, .json5            |
| plantuml        | text | PlantUML Class Diagram            | .puml, .plantuml, .pu, .iuml |
|===

`plantuml` (`reader-plantuml`) parses UML *class diagrams* via the official
MIT-licensed PlantUML library and has both a reader and a writer (round-trip
tested): classes are nodes, relationships are directed typed edges.

The reader formats already in the registry: adjlist, edge-list, dot, tgf, gml,
graphml, gexf, graph6, connected-json, ocif, and the RDF set (turtle,
n-triples, trig, trix, rdf-xml, json-ld, rdf-json). `neo4j-json` is the APOC
*export format* — distinct from the `neo4j` property-graph *model* entry.

`mermaid` is an umbrella that the `reader-mermaid` parsers split into eight
diagram-type sub-formats, each `..subformat of.. format:mermaid`:
`mermaid-flowchart`, `mermaid-class`, `mermaid-state`, `mermaid-er`,
`mermaid-c4`, `mermaid-mindmap`, `mermaid-sankey`, `mermaid-architecture`.

`plantuml` is likewise an umbrella; the (still-under-construction)
`reader-plantuml` covers one sub-format so far, `plantuml-class-diagram`
(`..subformat of.. format:plantuml`).

Added from the GraphInOut `ecosystem.adoc` survey (everything there that is a
format or tool, excluding graph datasets and application domains): formats `owl`
(Web Ontology Language) and `falcor-json-graph` (Netflix Falcor JSON Graph,
distinct from `jgf`); tools `boost`, `graph-tool`, `neo4j` (database, distinct
from the `neo4j` model), `memgraph`, `cytoscape-js` and `yed` in `tools.adoc`.

== Notes for homogenization

* `neo4j` is a `model`, not a serialisation; it currently has no `format-id` in the source. A slug `neo4j` is proposed above.
* *Versions checked against each homepage (2026-06):* biogrid-tab 3.0 (latest), gexf 1.3 (1.1 deprecated; 1.3 recommended), gjgf 0.1, gxl 1.0 (Dagstuhl-ratified), ocif 0.6 (Candidate Recommendation, Apr 2025), psimi-tab 2.5 (2.6/2.7 exist downstream but our entry is 2.5), sbml Level 3 Version 2 Release 2 (2019-03-29). Release dates still mostly need filling in.
* *GraphML:* two released versions, 1.0 and 1.1, each with its own XSD/DTD — `graphml-1.0` and `graphml-1.1`.
* *JGF:* a v1 and a revised v2 — `jgf-1.0` and `jgf-2.0` (v2 updated Jan 2020; GitHub releases still tagged 1.0).
* *XGMML:* treated as v1 — `xgmml-1.0`.
* *DOT has no standalone version:* the language evolves with Graphviz (HTML-like labels, new attributes are tied to Graphviz releases). Graphviz is currently at 15.0.0. `dot` stays an unversioned id; the version lives on the Graphviz tool.
* *Connected JSON is now at 8.0.0:* current spec is https://j-s-o-n.org/connected-json/8.0.0/ (7.0.0 and 5.0.0 archived). Registered as `connected-json-8.0.0`. The cc-gio source (`format-cj.json`) still describes the older "Strict v5.0.0 / v0.5" variant, so **the CJ reader must be upgraded to 8.0.0**.
* *Scotch & Harwell-Boeing added* (discovered via the gcv tool) — `formats/scotch/scotch.adoc` and `formats/harwell-boeing/harwell-boeing.adoc`. They have no source JSON; source column marked `(new, via gcv)`. Scotch's source-graph header carries a format version `0`; left as an unversioned id for now.
* *Discovered-format features were verified* against each authoritative spec in a second pass (conservative; undeterminable features omitted). Notable corrections: LEDA attributes downgraded to partial, phyloXML gained typed-edges (clade_relation), CX1 supports sub-networks while CX2 core dropped them, SBOL 3.1 supports edges-on-edges (Participation→Interaction), HELM/MCDL typed-edges removed.
* Category is `text` for most line-based formats — decide whether the tab-delimited formats (BioGRID, PSI-MI, VNA) deserve their own grouping or stay `text`.
* Label casing is inconsistent (`CytoScape JSON` vs `VOSviewer JSON`, bare acronyms like `GDF`/`GML`) — homogenize once ids are settled.
